# URL Shortener

A small FastAPI-based URL shortener using SQLAlchemy and Alembic for migrations.

**What this repo contains**
- FastAPI app: `main.py`
- SQLAlchemy models: `models.py`
- Database setup: `database.py`
- Pydantic schemas: `schemas.py`
- Alembic migrations: `alembic/`

**Requirements**
- Python 3.10+
- A running Postgres (or other SQLAlchemy-supported) database
- Recommended packages (install into a venv):
```
pip install fastapi uvicorn sqlalchemy alembic psycopg2-binary python-dotenv
```

If you prefer a `requirements.txt`, add the above packages to it and run `pip install -r requirements.txt`.

Environment variables
- `DATABASE_URL` — full SQLAlchemy URL, e.g. `postgresql://user:pass@host:5432/dbname`
- Put env vars in a `.env` file (this repo uses `python-dotenv` in `database.py`).

Local development
1. Create and activate a virtualenv:
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt  # or install packages listed above
```
2. Ensure `.env` contains `DATABASE_URL` for a local dev DB.
3. Generate a migration (autogenerate) and review it:
```bash
alembic revision --autogenerate -m "create urls table"
# inspect the new file under alembic/versions/
```
4. Apply migrations:
```bash
alembic upgrade head
```
5. Run the app:
```bash
uvicorn main:app --reload
```

Alembic & migration best practices (short)
- Use `--autogenerate` in development to create migration templates, then always review and edit before committing.
- Ensure `alembic/env.py` sets `target_metadata = Base.metadata` and imports your models so tables are detected.
- Point `DATABASE_URL` to the intended dev DB when autogenerating; Alembic diffs `target_metadata` against the live DB.
- Commit migration files to version control; keep migrations small and incremental.
- Run `alembic upgrade head` in CI/deploy to apply reviewed migrations automatically.

Common issues
- Empty autogenerated revision: you likely ran `alembic revision` without `--autogenerate`, or `env.py` lacks `target_metadata` or model imports, or `DATABASE_URL` points to a DB that already has the schema.
- Models not detected: ensure all models are imported in `alembic/env.py` (import side-effects are required so `Base.metadata` is populated).

Automation suggestions
- Add a small `Makefile` or `manage.py` for convenience (example shown below) to avoid memorizing commands.

Example `Makefile` targets
```
.PHONY: revision upgrade migrate

revision:
	@read -p "Message: " m; \
	alembic revision --autogenerate -m "$$m"

upgrade:
	alembic upgrade head

migrate: revision upgrade
```

Docker / container entrypoint note
- It's safe to run `alembic upgrade head` at container startup if migrations have been reviewed and committed. Do NOT autogenerate inside a container entrypoint.

Where to look
- Alembic config: `alembic.ini`
- Env script: `alembic/env.py`
- Generated migrations: `alembic/versions/`
