# URL Shortener

Short links with accounts, expiry, click analytics, QR codes and an admin area.
FastAPI + MySQL backend, React frontend.

```
.env        the one settings file for everything (ports, database, keys)
backend/    FastAPI app, Alembic migrations, tests, Dockerfile
frontend/   React app (Vite + TypeScript), Dockerfile
docs/       API reference (API.md) and OpenAPI schema, generated by `make docs`
compose.prod.yml, Caddyfile   production stack (see Deploying)
```

Run `make` to see every command.

## Quick start (Docker)

```bash
make up      # web http://localhost:3100, API http://localhost:8100/docs
make down
```

Migrations run automatically when the API starts. Data lives in a Docker volume and survives `make down`.

## Local development

The app runs on your machine with hot reload; MySQL (`mysql-dev`, :3307) and Redis (`redis-dev`, :6380) run in Docker.

```bash
make install   # once: Python and npm dependencies
make api       # starts MySQL + Redis, applies migrations, runs the API on :8100
make web       # in another terminal: frontend on :3100
```

To use other ports, change `WEB_PORT`, `API_PORT`, `VITE_API_URL`, `FRONTEND_URL` and `GOOGLE_REDIRECT_URI` in `.env` together.

Make yourself an admin after registering: `make admin EMAIL=you@example.com`.

## Configuration (`.env`)

One file at the repo root, read by the backend, the frontend (`VITE_*` only) and Docker Compose.

| Setting | Default | Purpose |
|---|---|---|
| `WEB_PORT`, `API_PORT` | 3100, 8100 | Ports on your machine |
| `VITE_API_URL` | http://localhost:8100 | Where the browser reaches the API (baked into the frontend build) |
| `DATABASE_URL`, `JWT_KEY` | required | Database and session signing key |
| `REDIS_URL` | empty | Rate-limit counters in Redis (shared by all workers, kept across restarts). Empty: in memory |
| `TOKEN_EXPIRE_MINUTES` | 30 | Session length (the frontend refreshes it while you're active) |
| `FRONTEND_URL` | http://localhost:3100 | CORS origin and where emails/Google sign-in send people |
| `COOKIE_SECURE`, `COOKIE_SAMESITE` | false, lax | Set `COOKIE_SECURE=true` behind HTTPS |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` | unset | Google sign-in |
| `REQUIRE_EMAIL_VERIFICATION` | true | New accounts must click the emailed link before creating links. Set `false` to skip locally |
| `SMTP_HOST` (+ `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_STARTTLS`) | unset | Without it, emails are printed in the API log |
| `RATE_LIMIT_ENABLED`, `RATE_*_PER_MIN` | on | Login 10, register 5, forgot-password 3 per IP; link creation 30 per user (per minute) |
| `CLEANUP_ENABLED`, `EXPIRED_LINK_RETENTION_DAYS`, `CLEANUP_INTERVAL_MINUTES` | on, 30, 60 | Deletes links that expired more than 30 days ago |

`.env` is committed on purpose, so its keys are public: fine on your machine, never in production.

## Deploying

`compose.prod.yml` runs everything on one server behind Caddy, which gets HTTPS certificates by itself.
`https://DOMAIN` serves the API and the short links, `https://app.DOMAIN` the web app.

1. Point two DNS `A` records at the server: `DOMAIN` and `app.DOMAIN`.
2. On the server, clone the repo and create `.env.production` next to `.env` (git ignores it). It overrides `.env`:
   ```env
   DOMAIN=rift.link
   JWT_KEY=...            # new one: python3 -c "import secrets; print(secrets.token_urlsafe(48))"
   DB_PASSWORD=...        # same command, URL-safe characters only
   DB_ROOT_PASSWORD=...
   SMTP_HOST=...          # optional: password-reset emails
   ```
3. `make prod` to build and start, `make prod-logs` to watch, `make backup` for a database dump in `backups/`.
4. Check `https://DOMAIN/health`, register on `https://app.DOMAIN`, then make yourself admin:
   `docker compose -f compose.prod.yml --env-file .env --env-file .env.production exec api python -m app.cli create-admin you@example.com`

The database has no public port, and the API reads visitors' real IPs from Caddy (`--proxy-headers`).
To update: `make backup`, `git pull`, `make prod`.

## Database migrations

```bash
make revision    # after changing models; review the generated file before committing
make migrate
make downgrade   # one step back
```

## Checks

```bash
make test   # backend smoke tests (in-memory SQLite, never touches your database)
make lint   # frontend lint + type-check
make docs   # after API changes: regenerates docs/ and the frontend's API types
```

CI runs the backend tests and the frontend lint + build on every push.

## API

Interactive docs at `http://localhost:8100/docs` (log in with `POST /auth/login` there; the cookie is then used
automatically) and `/redoc`. Full reference: [docs/API.md](docs/API.md).

Notes:
- Sessions are an HTTP-only cookie. Changing or resetting a password logs out every other session.
- Times are UTC.
- Clicks store the referrer's hostname, device, browser and a salted hash of IP + user agent (for unique visitors).
  Raw IPs are never stored.
- Behind a reverse proxy, rate limits and unique visitors need the real client IP (`uvicorn --proxy-headers`).

The frontend has its own notes in [frontend/README.md](frontend/README.md).
